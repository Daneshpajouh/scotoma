# Minimum covering number for a single-deletion pattern library

Scripts that check, by exhaustive computation, every quantitative claim in the
minimality result and the counterexamples that bound it. Each script needs only
the standard library and prints what it checked. Six of them read data, as
"Reading the output" below says; three of those need a third-party table that is
not released here.

Run them with any Python 3.9 or later:

    python3 verification/floor_theorem/verify_construction.py

## The statement being checked

For an alphabet of size at least four, a string of length at least twenty, and a
mismatch budget of at most five, the distinct single-base deletion patterns of
that string cannot be covered at that budget by fewer centres than there are
patterns, where the competing centres may be any words at all. The minimum is
attained by the patterns themselves.

## What each script establishes

| Script | What it checks |
|---|---|
| `canonical_relabelling_lemma.py` | Every coordinate of a deletion library carries at most two letters and switches between them at most once, so the canonical relabelling is a distance-preserving bijection. Exhaustive for lengths 2 to 8, plus 20,000 random 20-mers and adversarial shapes. |
| `verify_construction.py` | The witness family at budget five: distance to its own centre, distance to every other centre, and all pairwise distances, against the eighteen predicted values. |
| `verify_m4.py` | The same three conditions at every budget from one to five, obtained by restoring coordinates from the budget-five family. |
| `sweep_lengths.py` | The paper's own witness family at every budget from one to five and every length from 20 to 61, with the largest library at each length (N + 1 centres). The letters are read from the paper's table as printed (offsets 4, 6, 9, 12, 16 write 2, 3, 2, 3, 2; budget m uses the first m), so the letters at m = 1 and m = 3, which `verify_m4.py` does not run, are checked here. At every length and budget: distance exactly m to its own centre, more than m to every other, pairwise more than 2m, and each shift at least its value on the 19-cycle (t - m and t for shifts of 19 or more). Both rows of the printed nineteen-case table at m = 4 and m = 5 are compared value by value. At m = 5 it also measures that every four consecutive witnesses are pairwise at exactly 11, 1,575 windows. Three controls run every time and must fail: four offsets at budget five, letter 3 moved to offset 7, and one extra overwrite seen by the window check alone. About 1 s. |
| `scope.py` | How far the budget-four family reaches in length and run count, and where one extension of it stops. The m sweep extends the support with coordinates 17 and 18; that extension holds to m = 5 and fails at m = 6 and 7. That is one support failing, not a statement that no support works at those budgets. The expected YES and NO pattern is written into the script, which exits 1 if the run departs from it. |
| `pooled_counterexample.py` | The panel behind the body's 1,628, checked end to end from its released guide list `data/synthetic_panel_110.txt` (the original list, over the relabelled alphabet). The 1,628 belongs to this SYNTHETIC panel, not to the real CHANGE-seq panel of the next row, which has the same pattern count and needs all 1,629 balls by the pooled theorem. Checked here: 110 guides of length 20, pairwise disjoint libraries, 1,629 patterns, run counts 9 to 20, the redundant pattern and its 16 witnesses present in the library, and its radius-4 ball inside their union over all 341,716 words. The control, dropping one witness, runs every time. |
| `pooled_volume_bound.py` | The volume lower bound on covering the REAL pooled panel, computed from its 1,629 patterns in `data/pooled_patterns_1629.txt`, not from the synthetic panel of the row above: exact union 381,985,082 words, ball 341,716, so at least 1,118 centres, 68.6%. The body now prints this 1,118 (68.6%), changed on 2026-10-24 once this script had actually been run; it previously printed 839 (51.5%), which rests on the weaker sequential union bound of 286,613,932. Both are valid lower bounds on the covering number and 1,118 is the stronger; neither reaches the 1,629 the certificate proves. Measured 2026-10-24 at 187 s with a peak resident set of **27.4 GiB** (peak footprint 33.7 GiB), not the 11 GB an earlier note in this file and the script both claimed; budget memory accordingly. The 1,629 patterns in `data/pooled_patterns_1629.txt` are the distinct single-base deletions of the 110 guides of the CHANGE-seq measurement table of Lazzarotto et al. (2020): 1,634 counted guide by guide, 5 of them shared by guides offset by one base. The synthetic panel of the row above is written over 0123, matches the real one in guide count and pattern count, and has pairwise disjoint libraries, which the real panel does not. `pooled_patterns_producer.py` rebuilds the file from the CHANGE-seq table. |
| `pooled_patterns_producer.py` | Where the 1,629 patterns come from. Reads the CHANGE-seq table (not redistributed here; its source and SHA-256 are in the script), rebuilds `data/pooled_patterns_1629.txt` from its 110 guides and checks the result byte for byte: 110 guides over ACGT, 1,634 patterns guide by guide, 1,629 distinct, exactly 5 shared, each by two guides offset by one base and listed, SHA-256 b749f0869f5d4a97d1e6c6c48f750694dbec54460846ad4730b5cba76136fa02. The control, dropping one guide, runs every time and must change the digest. Prints the input table's SHA-256 so a run log shows which copy was read. |
| `pooled_floor_certificate.py` | The pooled theorem: the union of the radius-4 balls around the 1,629 distinct patterns in `data/pooled_patterns_1629.txt` cannot be covered by fewer than 1,629 radius-4 balls, centred anywhere. Reads those patterns and the 3,258 certificate words in `data/W_3258.txt`, two per pattern at distance exactly 4 and weight 1/2 each, and checks that every word lies in the union and that no radius-4 ball holds three of them (7,404 triples of these words lie pairwise within 8; an exact coordinate program rejects each). So no ball carries more than one unit, any cover needs 1,629 balls, and since the patterns cover the union the covering number is exactly 1,629. The same weights are a feasible dual of mass 1,629, so the fractional optimum is exactly 1,629 too; the per-pattern mass check gates both bounds. They cannot be rounded to one word per pattern: choosing one word per pattern with all chosen words more than 8 apart is a 2-SAT problem over 20,602 conflicting pairs, and it is unsatisfiable, every pattern's two choices in one strongly connected component. That is a fact about these words, not about every certificate. It reads no guide list: the five patterns two guides share by a one-base offset are single entries, counted once, never the 1,634 counted guide by guide. Four controls run every time: a planted third word in one ball that must be caught, a radius-5 rerun that must accept, two planted satisfiable 2-SAT instances that must come back satisfied (with x and not x rejected), and the clauses read back as word choices; the script exits 1 if any misbehaves. About 12 s. |
| `pooled_shared_check.py` | The five patterns two guides share, which are where a pooled bound could slip between 1,629 distinct and 1,634 counted guide by guide. Rebuilds the guides from the CHANGE-seq table as `pooled_patterns_producer.py` does, and requires the released digests of `data/pooled_patterns_1629.txt` and `data/W_3258.txt`. Checks that each shared pattern owns exactly 2 certificate words, not 4, each at distance exactly 4 from it and at least 5 from every other pattern, with mass exactly 1 in the ball centred at it; that in the guide-by-guide view exactly those 10 words fall inside two entries' balls; and that the 3,258 distinct words carry mass exactly 1,629. It does not repeat the whole-certificate check of `pooled_floor_certificate.py`. Six removal controls rerun every check on altered input (a sharing guide dropped; a sharing pair that is not offset by one; two words planted at a shared pattern; one shared pattern's words dropped; one of its words moved to distance 3; one moved to distance 4 from a second pattern) and must see the named checks fail. About 30 s. |
| `sound_patterns.py` | The sound-pattern theorem wherever it needs no input. Over every guide of length 4, 5 and 6 (N = 3, 4, 5), every budget m from 0 to N - 1, and every pattern of length N over ACGT plus a wildcard, with every word it accepts: inside m <= N - 2 no sound pattern carries a wildcard and the sound centres are exactly the library; at m = N - 1 the wildcard half still holds and sound centres outside the library appear for exactly the guides with run count 3 or more. Also: ACGTA at m = 2 (sound centres are the five library words, no four of them cover, the printed four-ball cover uses unsound centres accepting 4 and 8 words outside the union); CAGAG at m = 3 (eleven sound centres outside the library); the proof's step (iii) over all 19,920,075 cases to block length 19; and its step (iv) private points, 427,800 over every guide of length 4 to 7 that is not one repeated letter, at every 1 <= m <= N - 2. Controls run every time: the same enumeration over two letters must find sound wildcard patterns, step (iii) with a wrong coordinate must fail, and step (iv) with one change fewer must fail. About 20 s. |
| `sound_panel.py` | Steps (iii) and (iv) of the sound-pattern proof on the 110 real guides at m = 4, reading the guides from the CHANGE-seq table as `pooled_patterns_producer.py` does. Enumerates every centre using only library letters, 3,697,920 (2^(r-1) per guide), of which 1,634 are library words; shows each of the other 3,696,286 unsound by building the proof's step (iii) witness and checking it by distance; and builds and checks a private point for each of the 1,634. Checks that the weaker hypothesis m <= N - r + 1 would exclude 21 guides, those with r >= 17 at N = 19. It does not enumerate the panel's wildcard patterns or centres carrying a letter no library word uses (steps (i) and (ii), checked at small lengths by `sound_patterns.py`); there are 5^19 of them. The control, one coordinate fewer changed, must break both constructions. About 90 s. |
| `pooled_redundancy.py` | That a pattern of a pooled library can be redundant: B_4(p) lies inside the union of sixteen other patterns' radius-4 balls, so such a library needs one fewer ball than it has patterns. Checks the MECHANISM behind the body's 1,628 figure, not the 110-guide construction, which `pooled_counterexample.py` checks on the released list `data/synthetic_panel_110.txt`. Its control, dropping one witness, is part of the run and must leave the ball uncovered. |
| `sharp_threshold.py` | The shortest length at which a cyclic witness template exists at budget four, over every four-coordinate support and letter assignment of the template. It searches cyclic templates only, as its own docstring says, so it does not rule out a non-cyclic family at a shorter length. |
| `floor_counterexample.py` | That the statement is false outside its range: an exhaustive search showing four centres covering the union of five deletion balls. |
| `ball_overlaps.py` | Exact intersection sizes of two Hamming balls at every distance, and the volume lower bound they give, for comparison with the minimality result. |
| `cylinder_decomposition.py` | That a Hamming ball is exactly a union of cylinders, how many are needed, and how close that is to the information-theoretic minimum. |

## Reading the output

Every script prints the quantity it computed beside the value it was checking
against, and a control where one exists. `floor_counterexample.py` prints the
covering set it found, so the refutation can be checked by hand.

Six scripts read data. `pooled_counterexample.py` reads the synthetic guide
list `data/synthetic_panel_110.txt`, and `pooled_volume_bound.py` reads the
pattern list `data/pooled_patterns_1629.txt`, and `pooled_floor_certificate.py`
reads that list with the certificate words `data/W_3258.txt`; all three lists are
released here.
`pooled_patterns_producer.py` reads the CHANGE-seq table, a third-party dataset
that is not redistributed, and rebuilds the pattern list from it;
`pooled_shared_check.py` reads the same table with the pattern list and the
certificate words; `sound_panel.py` reads the same table alone. Each of the six prints the full SHA-256 of its input, the list or the table it is given,
so a run log shows which file was checked. Every other script operates on the alphabet directly and reads no file.
